## Deviations

- `anchorElement` is a Vue-only alias for `anchorRef` (`ColorPicker.vue:38`, `colorPicker.contracts.ts:50`). Upstream has only `anchorRef: RefObject<HTMLElement | null>`. Both feed `resolvedAnchorElement` (`ColorPicker.vue:124`); deviation is additive widening, not a drop.
- `popoverState` alias is `transposed` not `deviated`: upstream `popoverState` + `onPopoverState` is the controlled API; Vue exposes `popoverState` prop (same name) plus `v-model:popoverOpen` / `@update:popoverState` (`ColorPicker.vue:83,131`). The wiring through `effectiveOpen` with `popoverState ?? popoverOpen` precedence preserves semantics; the extra `v-model:popoverOpen` is a Vue-idiomatic alias. Previously un-wired alias is now `transposed`.
- `placeholder`/`gradientLabel`/`value` typing widens to Vue slots: upstream `placeholder?: ReactNode` can be an element; Vue `placeholder?: string` (`colorPicker.contracts.ts:90`) with `#default` slot as the escape hatch for richer nodes. Same for gradient label display.
- `children` → `#default` slot: upstream `children?: ReactNode` renders as value fallback (`ColorPicker.tsx: children`); Vue `#default` slot renders in `data-part="value"` (`ColorPicker.vue:299`).
- `valueClassName`/`swatchClassName` class merging uses `colorPickerSwatchSizes` map rather than upstream `SWATCH_SIZE` identifier name; values identical, name deviation only.
- Upstream `ColorPickerProps` inherits all `ButtonProps` via intersection (`ColorPicker.tsx:102`); Vue `ColorPickerProps` (`colorPicker.contracts.ts:42`) re-declares the Button surface explicitly rather than via `Omit` intersection, but the effective prop set is the same. No observable drop.
