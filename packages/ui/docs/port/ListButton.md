## Deviations

- `header` and `footer` accept both a string prop and a slot in Vue (`ListButton.vue:110–114`, `120–124`), while upstream accepts only `ReactNode`. The dual prop+slot pattern is a Vue convention; upstream's `ReactNode` covers both. Functionally equivalent but the typed API differs: upstream `header` is `ReactNode`, Vue `header` is `string` (`dataDisplay.contracts.ts:98`).
- `className` is not forwarded via `$attrs` in Vue (`ListButton.vue:61`); it is merged into `rootClass` and applied to `Button` directly. Upstream spreads `className` onto `Button` via JSX (`ListButton.tsx:121`). Same visual result, different forwarding path.
- `useComponentDefaults` is called (`ListButton.vue:41`) but the `uiContext` carries no `ListButtonDefaultProps` — the function returns the original props unchanged for this component.
- Upstream `ListButtonProps` inherits all `ButtonProps` via intersection (`ListButton.tsx:67–68`). Vue `ListButtonProps` (`dataDisplay.contracts.ts:84–119`) declares only the direct props, not the full `ButtonProps` set. Extra `ButtonProps` are not forwarded; the consumer must pass them through the `$attrs` passthrough.
- `multiline` is hardcoded to `true` in Vue (`ListButton.vue:93`) and upstream (`ListButton.tsx:130`). It is not exposed as a consumer prop in either version.
- `data-selected` is emitted in both (`ListButton.tsx:119`, `ListButton.vue:91`). Upstream uses `selected || undefined`; Vue uses `d.selected || undefined`. Identical result.
